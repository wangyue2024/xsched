## 1. 构建

```bash
cd xsched
cmake -B /tmp/xsbuild -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_CXX_COMPILER=/usr/bin/g++-13 \
  -DCMAKE_CUDA_COMPILER=/home/wy/cuda-12.9/bin/nvcc \
  -DCMAKE_CUDA_HOST_COMPILER=/usr/bin/g++-13 \
  -DCMAKE_CUDA_FLAGS="-ccbin /usr/bin/g++-13" \
  -DBUILD_TEST=ON -DPLATFORM_CUDA=ON
cmake --build /tmp/xsbuild --target halcuda shimcuda preempt utils -j8
```

探针（host 探针用 g++-13；`.cu` 用 nvcc `-arch=sm_120 -ccbin g++-13`）：

```bash
cd test/sm120_l3_trap_v2
./build.sh                 # 全部
./build.sh l3agent l3qspin # 指定目标
```

运行环境：

```bash
export LD_LIBRARY_PATH=/tmp/xsbuild/platforms/cuda:/tmp/xsbuild/preempt:/tmp/xsbuild/utils
export CUXTRA_CUDA_LIB=/usr/lib/x86_64-linux-gnu/libcuda.so.1
```

> 注意：`cudart` 通过 dlopen/dlsym 解析 driver 入口，所以 `LD_PRELOAD` 的 shim 抓不到
> `cuLaunchKernel`；受管 launch 要走 shim 自己导出的 `cuLaunchKernel`。

## 7. 常见坑

1. **`/tmp/xsbuild` 会被重启清掉**：重建时显式指定 g++-13 与 CUDA host compiler。
2. **GCC 15 不被 CUDA 12.9 支持**：用 g++-13。
3. **cudart 用 dlopen/dlsym**：LD_PRELOAD 的 shim 抓不到 `cuLaunchKernel`；要用 shim 导出的入口。
4. **`NO_PATCH` 语义曾反过**：旧实验（v2.6）因此作废，重跑前确认当前代码。
5. **ST.E 编码**：源寄存器在 w1 低字节，偏移在 w0 高 32 位；写错会越界 700。
6. **64 位指针**：`LDC` 只读低半会得到错误地址；必须读 `c[0x170]` 与 `c[0x174]` 两半。
7. **R1 不能覆盖**：handler 在 cave 返回后 `STL.64 [R1],R2`。
8. **`R2`(reason) 不能清零**：否则 handler 重执行 fault 指令。
9. **运行期改 cave 会被驱动串行化**：用预装 + 设备 writer；不要在内核运行时 host 写代码页。
10. **会话存在时 launch/代码写行为改变**：会话生命周期要显式管理（`KEEP_SESSION`/`FREE_AFTER_RESUME`）。
11. **0317 需要 ack**：无调试器时会阻塞；测试脚本默认套 cuda-gdb；现在可用 plain tracer。
12. **`0318` 在前台线程会永久阻塞**：不要在主路径同步调用。
13. **park 的 `Synchronize` 永远不返回**：测试要 `timeout`，并靠采样线程判断冻结。
14. **cuda-gdb 版本**：系统包 12.4；`-batch -ex run` 的 debuginfod 提示可忽略。
15. **证据优先**：任何"成功"都要 host 回读或计数器/stream 完成状态独立验证。

## 8. 上游 sm86/3090 复现（2026-10-26）

```bash
# 源码：XpuOS/xsched main（commit f49289f）。3090 到 github 的 git/codeload 不通时，
# 在 A100 上 clone 后 tar 过来。
cd /root/xsched-up
# 补 3rdparty/cuxtra（本地仓库的 include+lib）
# 补 3rdparty/ipc（include/src/tools + 3rdparty/boost-ipc）
# CMake 3.22：把 3rdparty/ipc/CMakeLists.txt 的 if (BUILD_TEST) 临时改 if (FALSE)
cmake -B build -DCMAKE_BUILD_TYPE=Release -DCMAKE_INSTALL_PREFIX=$PWD/output \
  -DSHIM_SOFTLINK=ON -DBUILD_TEST=ON -DBUILD_SERVICE=OFF -DPLATFORM_CUDA=ON \
  -DCMAKE_CUDA_STANDARD=17 -DCMAKE_CUDA_COMPILER=/usr/local/cuda/bin/nvcc \
  -DCMAKE_CUDA_HOST_COMPILER=g++ \
  -DCMAKE_CUDA_FLAGS="-arch=sm_86 -I/usr/local/cuda/include" \
  -DCMAKE_CXX_FLAGS="-I/usr/local/cuda/include" \
  -DCUDA_INCLUDE_DIRS=/usr/local/cuda/include \
  -DCUDA_LIBRARIES=/usr/local/cuda/lib64/libcudart.so
cmake --build build --target install -- -j32
LD_LIBRARY_PATH=$PWD/output/lib ./output/bin/cuda/level 3
```

- `level 3` 走 `CudaQueueLv3Trap`（默认 TRAP；`XSCHED_CUDA_LV3_IMPL=TSG` 才走 TSG）。
- 期望：preempt p50 ≈ 229 µs、restore ≈ 90 µs；`level 1` p50 ≈ 12–13 ms。
- 日志已存 `../evidence/ab_ampere/logs/`。
- 本地源码快照与一键脚本：`../evidence/ab_ampere/upstream/`
  （`xsched-main-f49289f.tar.gz`、`xsched-ab-a100-sm80.tar.gz`、`repro_ab.sh`、`UPSTREAM_INFO.md`）。
- A100（sm80）不在上游 TarpHandler 支持列表（只 sm70/sm86），不能直接跑 `level 3`。
