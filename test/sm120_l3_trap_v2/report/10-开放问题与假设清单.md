## 0. 使用说明

### 0.1 状态定义

| 状态 | 含义 |
|---|---|

| **部分验证** | 只在一个驱动/GPU/配置上做过 |

### 0.2 优先级

| 级别 | 含义 |

| **P0** | 决定路线是否成立；不做就无法判断下一步 |

| **P2** | 中价值；边界/部署问题 |
| **P3** | 低价值；锦上添花或暂不阻塞 |

## 2. 入口/触发类（Q-A）

### Q-A1 `pGpu+0x911` 的初值来源与开闸

- **问题/假设**：`0x911` 由 GPU init 时的某个 64 位能力/配置值决定；存在注册表键/模块参数/
  能力位可在 init 时置 1。若置 1，`0x20800122`/`0x83de031d` 会执行寄存器操作。
- **现状**：只知道 `__nvoc_init_dataField_OBJGPU` 里 `0x17354` 的位测试和
  `0x17376/0x17b4c` 两处写；无运行期 setter；5060/5090 都关。
- **实验**：
  1. 静态：反汇编 `0x17354` 前后，追 64 位值的来源（`ld` 偏移/调用/registry read）；
  2. 找字符串/表：`RM_ACCESS_REGISTRY`（0x4d）相关的键名；
  3. 专用机：设置键/模块参数 → 重载驱动 → `regops` 读 PTIMER/PMC；
  4. 若开：写 `0x419e84`，看 trap/reason；再跑 `l3x`/上游 payload。
- **判据**：成功 = PTIMER 非 0 + 写 `0x419e84` 出现 trap/停住；失败 = 仍 0/0x3a。
- **依赖**：裸金属/可控宿主 + root + 驱动重载（AutoDL 容器无 CAP_SYS_MODULE）。
- **优先级/风险**：**P0**；风险高（显示/计算共用机不要做）。
- **关联**：P1、L1、L12、E-01、ABI §8.5。
- **成功/失败**：成功 → paper-exact 可能；失败 → 只剩 P3/P4c/P6。

### Q-A2 第二条用户态入口

- **问题/假设**：除 `0x20800122`/`0x83de031d` 外，还有未 gate 的寄存器写/触发入口。
- **现状**：已枚举 RM controls、cuxtra、0317、tracer、BAR0；RPC 变体
  （`rpcGpuExecRegOps_v12_01`、`rpcCtrlDbgExecRegOps_v1A_10`、`rpcCtrlB0ccExecRegOps_v1A_0F`）
  未验证是否用户态可达/是否都检查 `0x911`。
- **实验**：静态找每个 RPC 的调用者/权限；动态用副作用判据（PTIMER 回读/计数冻结/签名）逐条测。
- **判据**：成功 = 任一入口让运行中内核停住；失败 = 全部 gate/权限/无副作用。
- **依赖**：无特殊机器；先做静态。
- **优先级/风险**：**P0**；低风险（只读/副作用判据；写触发需谨慎）。
- **关联**：P3、L2、E-01、ABI §8。
- **成功/失败**：成功 → 绕过 gate；失败 → 强化"仅 0317/GDB"。

### Q-A3 `0x419e84` 在 Blackwell 上是否仍是 trigger

- **问题/假设**：地址/bit31 在 sm120 仍有效（libcuda 595 有 13 处硬编码；570 可用）。
- **现状**：sm120 上无法执行（gate），所以未验证；地址在 550/570/595 libcuda 都存在。
- **实验**：仅在 Q-A1 开闸后写候选；对比 3090 的 reason/行为；扫相邻 bit/地址。
- **判据**：与 0317 不同的 reason/trap；失败 = 无效果/异常。
- **依赖**：Q-A1。
- **优先级/风险**：P1；写未知寄存器有风险。
- **关联**：P1、E-01、ABI §8.5。

### Q-A4 595 装到 Ampere（驱动 vs 架构）

- **问题/假设**：`0x911` 的关闭是 595 驱动策略，还是 Blackwell 架构策略。
- **现状**：3090/570 开、A100/550 开、5060/5090/595 关；缺 595-on-Ampere 交叉。
- **实验**：3090（sm86）+ 595（若支持）跑 `regops`；A100（sm80）+ 595（若支持）。
- **判据**：PTIMER 非 0/门开 = 驱动版本；门关 = 架构/组合。
- **依赖**：可装驱动的 3090/A100 机器。
- **优先级/风险**：**P0**；中风险（装驱动）。
- **关联**：P6b、L1、E-01、ABI §10。

### Q-A5 H100/H200、数据中心 Blackwell 的 regops

- **问题/假设**：数据中心 SKU 是否开放 reg-op/带内触发。
- **现状**：未测；5090（消费 Blackwell）关。
- **实验**：租 H100（sm90）/B200；跑 `regops` 读 PTIMER/写 `0x419e84`；看 handler 支持。
- **判据**：门开/门关；trap 是否进入。
- **依赖**：硬件/租用。
- **优先级/风险**：P1；低风险（只读优先）。
- **关联**：P6、ABI §10。

### Q-A6 BAR0 直写（高风险，仅专用机）

- **问题/假设**：不经过 RM，直接 `mmap` BAR0 写 `0x419e84` 能否触发 trap。
- **现状**：未做；需要 root；共用显示 GPU 风险极高。
- **实验**：专用机 + 快照；先读 BAR0 确认地址空间，再写；准备好恢复。
- **判据**：不经过 RM 也能停/进 handler。
- **依赖**：专用机/root/快照。
- **优先级/风险**：P2；**高风险**；不要在 5060 上做。
- **关联**：P2、L12、Runbook §7。

## 3. 通道/目标类（Q-B）

### Q-B1 host→trap 的 target/request 通道

- **问题/假设**：存在一条 host 可写、trap 可读的通道，能携带 per-suspend target/request。
  候选：开闸后驱动写 pbuf；调试 agent accessor；新通道。
- **现状**：pbuf 全 0；host/设备写失败；trap store 不共享；只有常量/SR 可读。
- **实验**：
  1. 开闸后看驱动是否写 `pbuf+4/+8`；
  2. 调试 agent 用 `IPreemptionBufferAccessor` 写；
  3. 扫 scratchpad/其他 memobj 的写入口。
- **判据**：trap 读到非 0 target/request，且能按它选择。
- **依赖**：Q-A1 或 Q-C1。
- **优先级/风险**：**P0**；中高风险。
- **关联**：P1/P4c、L3/L4、E-05、N3、ABI §5/§7。

### Q-B2 正常 trap 能否读全局内存

- **问题/假设**："trap 读全局=0"只对 0317 debugger-suspend 上下文成立；正常带内 trap 可读。
- **现状**：0317 陷阱读 0；3090 的 payload 用 `LD.E` 读 preempt buffer；sm120 带内 trap 不可达。
- **实验**：3090 正常 trap 里读一个 host magic；sm120 开闸后复测。
- **判据**：读到非 0 = 正常上下文可读；仍 0 = 读通路问题。
- **依赖**：3090 或 Q-A1。
- **优先级/风险**：P1；低风险。
- **关联**：E-03、L3、ABI §7。

### Q-B3 pbuf store 是否永远不共享

- **问题/假设**：trap 对 pbuf 的 store 落到私有/快照映射，驱动看不到。
- **现状**：0317 陷阱 ST 不 fault，但写 1/2 行为相同；launch trap 700。
- **实验**：开闸/agent 写后观察 `do_read` 是否采用；换地址/大小/写序；加 membar。
- **判据**：驱动行为随 store 变化；失败 = 仍无效果。
- **依赖**：Q-A1/Q-C1。
- **优先级/风险**：P1；中风险（可能破坏状态）。
- **关联**：E-05、P-09、ABI §5。

### Q-B4 scratchpad 作为 mailbox

- **问题/假设**：scratchpad 有驱动不用的槽位，可做 host↔trap  mailbox。
- **现状**：per-warp 0x2a0；只覆盖活动记录；盲访 700；`+0x29d` 是 defer 状态。
- **实验**：静态布局 + 生命周期；找不写/不复位的槽；host rw-s 写 + cave 读；多次 trap 验证。
- **判据**：稳定读写且不影响 CILP；失败 = 700/被覆盖。
- **依赖**：无。
- **优先级/风险**：P2；中风险（破坏 CILP）。
- **关联**：L5、ABI §6、compendium/04。

### Q-B5 reason 是否有 XSched 专用位

- **问题/假设**：开闸后 cmd=2 产生 `0x30`（0x10|0x20）或其他专用位，可区分"XSched 请求"。
- **现状**：当前 0317=0x1、launch=0x8；cmd=2 未出现。
- **实验**：开闸后写 pbuf cmd=2；cave 记录 R2；对比 0317/launch。
- **判据**：0x30/专用位；失败 = 仍 0x1/0x8。
- **依赖**：Q-A1。
- **优先级/风险**：P1；低风险。
- **关联**：E-04、N2、ABI §2.2。

### Q-B6 多 kernel/queue 只杀目标

- **问题/假设**：有了 target 通道后，handler 能只 EXIT 目标 kernel，其余继续。
- **现状**：现有单流单 kernel；多 kernel 未验证；0317 context 级。
- **实验**：同 context 两个 kernel；cave 按 kernel_idx/target 选择；测 target 退出/其余完成。
- **判据**：只目标退出、其余 bit-exact；失败 = 误杀/context 崩。
- **依赖**：Q-B1。
- **优先级/风险**：**P1**；中风险。
- **关联**：P5、L10、N4、E2。

## 4. 恢复/动作类（Q-C）

### Q-C1 进程内调试 agent 的 CILP 保存/恢复

- **问题/假设**：只用 libcuda/libcudadebugger（不靠 cuda-gdb 进程）就能写 pbuf cmd=2/1、
  保存/恢复 CILP，实现 park/resume。
- **现状**：`DebugAgentMain` 参数/协议样本已抓；`IPreemptionBufferAccessor` 字符串已知；
  `cudbgApiInit/Attach` 单独不改变 0317。
- **实验**：复刻 gdb↔agent 帧、注入、会话；写 pbuf；测 park/resume；对比 cuda-gdb。
- **判据**：无 cuda-gdb 也能停/恢复，结果 bit-exact。
- **依赖**：Q-A1 不一定；需要逆向/注入。
- **优先级/风险**：**P0**（长期）；高工作量。
- **关联**：P4c、L11、ABI §9、RM_REVERSE。

### Q-C2 0318 的用户态释放路径

- **问题/假设**：某个 client/session/调试器命令能让 0318 返回并恢复。
- **现状**：app/agent 两个 client 都阻塞；再 attach 挂死；park 不可释放。
- **实验**：调试 agent continue；不同 session 组合；0318 前先 0317{0,0}/模式；超时/线程隔离。
- **判据**：0318 返回 + 计数恢复；失败 = 仍阻塞。
- **依赖**：Q-C1 或 cuda-gdb。
- **优先级/风险**：P1；中风险。
- **关联**：P4a/P4c、L6、E-09、doc05 §2.2.2。

### Q-C3 裸 EXIT 的安全重定向

- **问题/假设**：通过 trampoline/TRAP_RETURN_PC/guard 的不同组合，EXIT 后重放仍成功。
- **现状**：reason-armed EXIT 27.4 ms + final 700；guard 路径 0.234 s；不能混为一谈。
- **实验**：多种返回重定向；对比 native cancel；测重放/正确性。
- **判据**：早退 + 重放成功 + 无 700；失败 = 700/丢工作。
- **依赖**：无（单机）。
- **优先级/风险**：P1；中风险。
- **关联**：P5、L7、E-08/P-14、exp_reason_arm_exit。

### Q-C4 非幂等/device malloc 的重放边界

- **问题/假设**：重放只对幂等 kernel 安全；device malloc/累加/随机应失败或结果错。
- **现状**：只验证 `C=A+B` 幂等；device malloc 红灯未实测。
- **实验**：累加 kernel、随机 kernel、device malloc/free kernel 各一组；suspend/resume 后比对。
- **判据**：结果正确/错误可预测；给出"不可抢占"清单。
- **依赖**：无。
- **优先级/风险**：P2；低风险。
- **关联**：doc05 §3.3、L10。

### Q-C5 多队列重放顺序/一致性

- **问题/假设**：多 XQueue 同时 suspend/replay 时，顺序/依赖保持一致。
- **现状**：只单队列。
- **实验**：两队列交替 suspend/replay；有依赖的两个 kernel；测结果/顺序。
- **判据**：结果正确、无死锁；失败 = 顺序错/丢命令。
- **依赖**：无。
- **优先级/风险**：P2；中风险。
- **关联**：P5、L10、doc05 §3.4。

## 6. 工程/移植类（Q-E）

### Q-E1 5090 managed kill 校准

- **问题/假设**：5090 的 3.4 s / `devflag=0xffffffff` 是 pbuf/时序未校准，校准后可复现 0.234 s。
- **现状**：handler 布局一致；0317 签名可用；kill 流程 PARKED/release 失败。
- **实验**：重读 `do_read+0x120/0x130`；对齐 arm/devflag 时序；重跑 8/20 s victim。
- **判据**：0.234 s + 正确重放；失败 = 595.71 行为不同。
- **依赖**：5090（或同类）。
- **优先级/风险**：**P1**；中风险。
- **关联**：E-10、L8、doc03 §3.8。

### Q-E2 A100/550 cuxtra 崩的绕过

- **问题/假设**：绕过 `cuXtraKernelGetFunction`（用 CUfunction 直接构造 managed launch），A100 带 shim 可跑。
- **现状**：带 shim SIGSEGV；无 shim 33–46 ms；sm80 handler 缺。
- **实验**：绕过函数；构造 params/entry；测 launch；补 sm80 handler。
- **判据**：A100 带 shim 可跑/可停；失败 = 550 兼容性。
- **依赖**：A100 机器。
- **优先级/风险**：P2；中风险。
- **关联**：L9、A/B、compendium/07。

### Q-E3 sm80/sm90 handler 端口

- **问题/假设**：SM86 payload 的语义可移植到 sm80/sm90。
- **现状**：sm86 `+0x3e0 IADD3`；sm80 不在上游列表；sm90 未测。
- **实验**：反汇编 sm80/sm90 handler；找 patch 点；注入测试。
- **判据**：trap 可执行/可杀；失败 = 结构不同。
- **依赖**：A100/H100。
- **优先级/风险**：P2；中风险。
- **关联**：L9、A/B。

### Q-E4 GDB 延迟再降

- **问题/假设**：116/106 ms 可降到 <50 ms（持久 gdb/批量/预热/优化 MI）。
- **现状**：attach 23 + CILP 80；会话复用无效；`-exec-interrupt` 不冻结。
- **实验**：持久 gdb、批量 attach、并行预热、减少 MI 往返；测 n=10。
- **判据**：<50 ms 且 bit-exact；失败 = CILP 80 是硬下限。
- **依赖**：无。
- **优先级/风险**：P2；低风险。
- **关联**：E-06、doc05 §4.1。

## 7. 论文/理论类（Q-F）

### Q-F1 论文 target 的真实语义

- **问题**：论文的 target 是不是 host 写的 ID？
- **现状**：**已确认不是**：queue 触发范围 + `kernel_idx`/`preempt_idx` 记账；
  handler 读 preempt buffer（`inject.cu`）。→ 可作为已关闭项。
- **判据**：原文 §6.3 + 代码；已闭环。
- **关联**：doc05 §2.2、compendium/03 §12。

### Q-F2 32 µs 的成立条件

- **问题**：32 µs 需要哪些条件？sm120 缺哪一项？
- **现状**：带内触发 + handler abort + stream 立即完成；sm120 缺带内触发；27 ms 是驱动收尾。
- **实验**：3090 上逐步引入/移除条件；开闸 sm120 后复测。
- **判据**：分解出 32 µs 的预算；记录。
- **优先级/风险**：P1（理论/汇报）；低风险。
- **关联**：doc05 §5、doc07 N4。

### Q-F3 四道锁框架的普适性

- **问题**：触发/请求/输入/恢复四道锁是否适用于其他 XPU/驱动。
- **现状**：只在 sm120/595 与 3090/A100 上使用；未形式化。
- **实验**：套到 A100/H100/其他平台；看是否预测行为。
- **判据**：框架能解释/预测；失败 = 仅 sm120。
- **优先级/风险**：P2；低风险。
- **关联**：doc04 §1、doc07 N1。

### Q-F4 幂等性分类/自动化

- **问题**：如何自动判定一个 kernel 是否可被 L3 抢占（幂等/无 device malloc/无累加）。
- **现状**：论文手工/先验；我们只测 `C=A+B`。
- **实验**：静态/动态检查（device malloc、atomic、global 写）；小样本验证。
- **判据**：能给出可抢占/不可抢占；失败 = 只能手工。
- **优先级/风险**：P3；低风险。
- **关联**：doc05 §3.3、P5。

## 9. "不要再试"清单（已知不可行/高风险）

1. 在共用显示的 5060 上 BAR0 直写 / `rmmod` / 未知寄存器写；
2. 用内核漏洞/越权绕过 gate；
3. 无应答者的 0317（会阻塞）；
4. 裸 EXIT（破坏重放）；
5. scratchpad 盲写/盲读（700/破坏 CILP）；
6. 写 `trap_reason_table`（下一次 trap 700）；
7. 会话存在时运行期 host 写 cave/handler（串行化）；
8. `-exec-interrupt` 复用会话（不冻结）；
9. 对受保护/setuid 进程 ptrace（权限）；
10. 换驱动后继续用旧 `base`/pbuf 偏移（必须先跑 checklist）。
