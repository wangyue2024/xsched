## 一页结论

1. **生产可用 L3 已交付**：GDB backend（`GdbInterruptContext` + `l3ctl` + `xcli l3`），
   设备静止 116 ms、预热后 attach ~23 ms、handover 0.73–0.74 s、`Resume=1`。
2. **trap-native 的"停"已打通**：RM `0317` 在受管上下文 27–30 ms cancel，
   设备真正停住可到 0.204 ms；外部 tracer 预置时可 park（但不可释放）。
3. **trap-native 的"杀 + 重放"已闭环**：standalone 8 s → 0.234 s `cudaSuccess`；
   受管队列可记录并重放被杀内核；裸 `EXIT` 会破坏重放（v6.8）。
4. **判据从"完全不可用"推进到"事件可分、目标不可选"**：当前配置下
   `0317 = 0x1`、`launch = 0x8`；handler 能读自己的 `kernel_idx` / `killable`；
   仍缺 per-suspend 的 **target ID** 和 **request** 的 host→trap 通道。
5. **论文方法在 sm86/570 上复现成功**：`level 3` p50 230–241 µs、restore 93–127 µs、
   200 次 suspend/resume 后结果 `bad=0`；sm120/595 卡在 `pGpu+0x911` 关闭 regops。
6. **sm120 的根因**：不是 handler 机制，而是**中断入口被软件关闭 + 请求/目标通道缺失 +
   恢复归调试器状态机**。纯用户态"停住且可恢复"不可达，除非实现进程内调试 agent
   或打开 `pGpu+0x911`。
