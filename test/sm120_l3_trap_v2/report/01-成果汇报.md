## 0. 一页结论

**一句话**：

> 论文的 queue-based L3 在 3090/570 上跑通（229 µs、bad=0）；
> 在 sm120/595 上，**带内入口被驱动启动期关闭**，我们交付了 **GDB/0317 两条结果层替代**，
> 并把 **trap/driver ABI 完整逆向**；论文原机制在当前配置下不可实现。

| # | 核心观点 | 一句话 | 关键数字 | 详见 |
|---|---|---|---|---|
| **1** | **入口被关** | 595/Blackwell 关闭用户态可达的 reg-op，论文的带内触发不可用 | PTIMER=0；写 `0x419e84` status 0x3a；3090 对照 229 µs | `02`、`03` |
| **2** | **两条替代** | GDB 冻结/恢复、0317 停/杀+重放，是**结果层** L3 | GDB 116/106 ms；0317 27–30 ms；kill 0.234 s | `04` |
| **3** | **2.5 段 + 下一步** | 三段耦合完成 2.5 段；缺 target 通道与带内触发 | 0.204 ms 停 vs 22.9–30 ms 返回；pbuf 全 0 | `05` |

**做到了 / 没做到**：

| 做到了 | 没做到（当前配置） |
|---|---|
| GDB L3（suspend/resume，bit-exact） | 论文 32 µs 带内 L3 |
| trap 注入/签名/kill+replay（0.234 s） | 按 queue 选择目标 |
| trap/driver ABI、RM 0x83de、调试器栈 | 不依赖 cuda-gdb 的完整恢复 |
| A/B：3090 229 µs、bad=0 | sm120 原地 suspend/resume（0317） |

## 2. 核心观点 1（02+03）：论文入口被 595/Blackwell 关了

**论文的触发**：`cuXtraTriggerTrap` → RM `0x20800122` → 写 GPU 控制寄存器 `0x419e84`（bit31）
→ 全局 stall → 正常上下文 trap → handler abort。

**实测证据**：

| 证据 | 结果 |
|---|---|
| 内核 gate 检查 | `0x2dd122`/`0x21a9cc` 在写寄存器**之前**检查 `pGpu+0x911` |
| `0x911` 初值 | 全二进制仅两处 init 写（`0x17376/0x17b4c`），无运行期 setter |
| subdevice 路径 | gate=0 → **NV_OK**，跳过写 |
| 会话路径 | gate=0 → **0x56**，不进执行 |
| 5060/5090 动态 | PTIMER/PMC **读 0**；写 `0x419e84` status **0x3a**，无副作用 |
| 对照 3090 | 同一套上游代码：`level 3` **229 µs**、200 次抢占 `bad=0` |
| 对照 A100 | regops 开，但 sm80 handler 缺 → 内核照跑 |

**结论**：

- **不是 handler 不会执行**（签名/注入/0317/GDB 都通）；
- **不是 Blackwell 架构不支持**（3090 同码跑通）；
- 是 **595/Blackwell 的驱动策略**在启动期把 reg-op 关了；
- 因此 **论文的 queue-based 带内 L3 在当前 sm120/595 配置下不可实现**。

详见 `02`（证据链）、`03`（结论与 E1–E9 强度）。

## 3. 核心观点 2（04）：两条结果层替代

### 3.1 GDB：attach=冻结 / detach=恢复

- 机制：cuda-gdb MI2 + ptrace + libcudadebugger/cudbgApi；驱动保存/恢复 CILP；
- **不需要我们的 handler/cave**；目标只需 `PR_SET_PTRACER_ANY`；
- 冻结对象：**进程 + 其 CUDA context**（同一 context 的所有 stream 停；host 线程停）；
- 让出 SM：B 33.65 s → 0.74 s；**显存不释放**（624→634 MiB 实测）。

| 指标 | 数值 |
|---|---|
| 设备静止（冷 / 预热） | **116 / 106 ms**（attach 23 + CILP 80） |
| 恢复 | detach 8–10 ms / continue 1–3.5 ms |
| 正确性 | **bit-exact** |
| 端到端 handover | 0.73–0.74 s（含脚本 0.5 s sleep） |

### 3.2 0317：RM 调试器 suspend

| context 状态 | 0317 结果 | 关键数字 |
|---|---|---|
| 普通 context | benign trap（内核继续） | 签名 `0x5aa5/0x1` |
| 受管 + `InstrMemAllocator`（默认） | **context 级 cancel** | 27–30 ms；设备停 **0.204 ms** |
| 受管 + `NO_ICTX_INSTRMEM` | no-op | 不停 |
| 预 attach / tracer | park（stop-only） | 0318 阻塞，不可释放 |

- **停**：设备 0.204 ms；`Suspend` 返回 22.9–30 ms（驱动 teardown + stream 同步）；
- **恢复**：不能原地；**XQueue 重放**（8 s → 0.234 s）；0318 ≠ 重放；
- **寄存器/显存**：cancel 丢寄存器现场；显存不释放；host `cudaMalloc` 可幂等；
- **cave 执行 ≠ 决策权**：受管 + InstrMem 下 cave 可执行（R2=0x1），但驱动仍 cancel。

### 3.3 与论文的边界

| 维度 | 论文 | GDB | 0317 |
|---|---|---|---|
| 机制 | 带内注册写 + 正常 context | cuda-gdb | RM 调试器 suspend |
| 粒度 | hwQueue 目标 | 进程/context | context |
| 延迟 | **32 µs** | 116 ms | 27 ms |
| 恢复 | host 重放幂等 kernel | 原地 resume | 不能原地；重放 |
| 依赖 | 驱动/硬件入口 | cuda-gdb | 0x83de 会话 + 应答 |

**结论**：两条都是**结果层替代**（停住/让渡/恢复或重放），不是机制/性能等价。
详见 `04`。

## 4. 核心观点 3（05）：2.5 段与下一步

**论文快路径 = 三段耦合**：

| 段 | 我们 | 状态 |
|---|---|---|
| stage1 managed launch（shim/guardian/params） | XSched HAL | ✅ |
| stage2 instrumented handler（cave） | `+0x390` / 8 槽 / 指纹 | ✅ |
| stage3 带内触发（`0x419e84`） | **0317 带外** | ⚠️ 不是论文触发 |

**当前是 2.5 段**：能 trap、能 cave、能 kill/重放；但第三段是带外 0317，不是带内。

**两个缺口**：

1. **target/request 通道（N3）**：pbuf 全 0；host/设备写不进；常量只有自己的 idx；
   → 缺口是**通道**，不是一个字段；
2. **决定权/延迟（N4）**：0317 是 context 级；27 ms 是驱动收尾；
   target 只提升选择性，不降延迟；32 µs 要带内触发。

**下一步（P1–P6）**：

| 路径 | 目标 | 首实验 |
|---|---|---|
| **P1 开闸** | paper-exact | 找 `0x911` 能力位；专用机置 1 |
| **P3 第二入口** | 绕 gate | 枚举 RPC 变体/escape |
| **P4c 调试 agent** | 纯用户态完整路径 | libcudadebugger/CILP |
| **P5 kill+replay** | 保底可用 | XQueue 重放 |
| **P6 换平台** | 论文级结果 | 3090/570、GV100 |

详见 `05`（N1–N4、L1–L12、三个近期实验）。

## 5. 关键证据：A/B、5090、延迟

### 5.1 A/B

| 机器 | 结果 |
|---|---|
| 3090 L3 ×3 | p50 **230.8 / 231.4 / 227.3 µs**；dead-loop 241/231/235 µs；restore 93–127 µs |
| 3090 正确性 | 200 次抢占后 16M 元素 **bad=0** |
| 3090 去 shim | **6–40 ms** |
| 3090 L1/L2/TSG | 13.38 ms / 1.257 ms / 13.35 ms |
| A100/550 | 带 shim **SIGSEGV**；无 shim 33–46 ms |
| 5090/595.71 | regops **同关**；handler 布局一致；GDB/0317 可用；managed kill 3.4 s（0.234 s 未复现） |

### 5.2 延迟账本

| 场景 | 数字 |
|---|---|
| 论文 Lv3 | **32 µs** |
| 3090 Lv3 | **229 µs** |
| sm120 GDB 设备静止 | 116 ms（预热 106） |
| sm120 0317 设备停 | **0.204 ms** |
| sm120 0317 `Suspend` 返回 | 22.9–30 ms |
| sm120 kill+replay | 0.234 s |
| sm120 裸 EXIT | 27.4 ms + final 700 |

**一句话**：设备"停"不慢（0.2 ms 级）；23–30 ms 是驱动收尾，116 ms 是 CILP 保存；
论文 32 µs 的前提是 handler 内 abort 让 stream 立即完成。

## 7. 决策建议

| 目标 | 建议 | 代价 |
|---|---|---|
| 尽快可用 | GDB backend + 预热 cuda-gdb；接受 116 ms | 低 |
| 研究论文路径 | 先 P1 开闸 / P3 第二入口；P6b 3090+595 控制 | 中高 |
| 纯用户态 | P4c 进程内调试 agent | 高（月级） |
| 保底可用 | P5 kill+replay（27 ms） | 中 |
| 论文复现 | 3090/570（已验证）或 GV100 | 硬件 |

**建议**：如果交付优先，锁定 GDB；如果研究目标必须 sm120 trap-native，
把资源集中到 **P1 开闸** 与 **P4c 调试 agent**；不要在 RM 命令里继续找 mailbox。
